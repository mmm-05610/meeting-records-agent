目标是形成首个可运行产品。现状只有文档；不要把目录规划、上游已有功能和本项目已经完成混在一起。

## 并行角色与写入范围

角色是分工建议。执行者可以使用自己已有的多 Agent 能力；没有该能力时按同一依赖串行，不另建调度平台。

| 角色 | 独占修改 | 共享约束 |
|---|---|---|
| I 集成负责人 | 根目录配置、Compose、依赖锁、共享契约、Web 全局装配、联调测试、任务总账 | 合并后才让依赖方继续；只由它运行共享验收栈和修改任务状态 |
| R 文档检索 | `apps/rag/` 业务适配及组件测试 | ingest 与 delete 串行，避免同时改 router/service |
| A Agent 服务 | Agent `service/`、`schema/`、`memory/` 及对应测试 | schema 在 T003/T007 结束后冻结给图与 UI 使用 |
| B 检索工具与图 | Agent `agents/tools.py`、`agents/rag_assistant.py` 及对应测试 | T008 可与 A 并行；图任务等服务/历史契约完成 |
| W1 Web 服务边界 | `pages/api/`、`context/UserContext.tsx` 及对应测试 | 不修改全局 package/lock/_app；通过 I 接入 |
| W2 Web 界面 | documents/collections/chat 页面、具体 ChatDemo 组件及 UI 测试 | 上传与聊天有不同文件集；同一人或任务结束交接，禁止两人改同一个文件 |
| E 评测 | `evals/`、模拟数据和去敏结果摘要 | 不修改生产图以迎合验收题；冻结题集只读 |

可以使用现有 Git worktree 或共享工作目录。worktree 必须先合并前置任务提交；共享目录必须严格声明写入文件，遇到交集就串行或交给所有者。不要同时改一个 pyproject/package.json/锁文件。`.run/v0.1/status.md` 由 I 更新，工作者各写独立回执文件。

## 运行资源隔离

- 组件任务优先用局部 fixture，不启动多套相同端口的服务。
- 必须起服务的并行任务使用独立 Compose project 名、数据库、端口和数据卷，记录在 `.run/v0.1/resources.md`。
- T015 起共享集成栈只归 I 使用；其他人不得同时迁移、重建、清卷或导入破坏验收数据。
- 真实模型评测排队执行，使用同一冻结模型配置；避免并发限流把模型结果污染成随机失败。
- 每次清理只处理本项目登记资源，禁止用全局 prune 或删除其他项目数据。

## 配置与模型前置条件

T001 仅检查必要凭据是否可用，不输出密钥。T004 生成来自实际设置对象的 `.env.example`，说明配置来源与联网条件；不先造一组上游不识别的环境变量。

如果缺生成/embedding 凭据，继续实现与模拟检查，标记 T022/T023 的真实路径阻塞，并给出最少需要的配置名和注入位置。不得借用其他项目密钥、开启未授权付费服务或以 fake model 生成验收结论。重排模型版本和中文效果同样需要真实验证。

## 迁移、退役与失败处理

这是新产品，运行数据由上游迁移建立，不设计历史业务迁移器。保留卷与备份；改变 embedding 模型/维度需要按上游索引重建流程处理，不能混用向量。

退役 Chroma 示例检索、旧 R2R conversation/SSE 聊天和 R2R 第二套 Agent 运行依赖。注册表、路由、设置、依赖和文档一起检查；不要仅在 README 宣布退役。

网络断开先保存已完成证据和当前操作标识，恢复后检查远端/本地实际结果再重试。Git 推送、导入、迁移、容器创建等不得因为超时就认定完全没发生。恢复规程见 [resume.md](operations/resume.md)。

## 交付物

完整应用源码及适配记录、依赖锁和无密钥配置模板；可执行的安装/停止/备份说明；三份最小演示文件及完整评测数据；实际验收表与去敏证据索引；模型配置和已知限制；最终 Git 提交、运行入口及恢复调度清理回执。

时间预算不改变范围和质量。若窗口结束仍有未通过项，交付准确进展与下一步，不宣布 v0.1 完成，也不悄悄建立无限期恢复循环。
