## 设计依据与授权范围

接受记录标识：`ACCEPT-V01-DESIGN-CHAT`，类型为用户明确认可既有详细设计。来源是本项目会话中，在详细设计交付后认可并要求创建项目的消息；没有独立消息编号可供外部校验，不伪造签名、回执或正式 DID 应用记录。

本次直接授权是编写详细架构、模块设计、任务依赖、最终验收和 dsh 工作目标。新增的夜间恢复要求来自本次用户指令。上述授权允许本次落盘文档；本次不实际执行产品开发或创建调度。用户后续向 dsh 发出的 `/goal` 是实施的直接指令。

## 执行者可自主完成

- 在固定上游中调整配置、提示词、接口绑定和已有业务流程；编写必要胶水代码与回归测试。
- 在保持行为和契约的前提下解决依赖冲突，选择私有辅助函数、文件拆分、日志格式和测试工具；记录补丁来源及理由。
- 基于既有配置选择可用模型，固定模型名、embedding 维度、重排权重及预算，使用调试集调参。
- 按任务依赖并行开展互不冲突的工作；独占共享文件和联调资源。
- 在新项目目录内运行服务、测试、构建和分阶段本地 Git 提交。凭据使用执行环境已授权的配置，不采集其他项目的密钥。

## 不能悄悄改变的决定

功能模块必须二次开发；三个应用服务；LangGraph 为唯一 Agent 编排；Agent 与 R2R 通过 HTTP 分离依赖；项目/会议由 R2R 管理，历史由 LangGraph checkpoint 管理；决定类问题不能用 top-k 冒充完整会议核对；不扩展团队权限、自动入会、ASR、MCP、任务派发或新的基础设施平台。

模型供应商、具体权重、运行预算的选择属于有实测约束的工程选择。若必须更换核心基座、改变数据所有权或削减验收才能继续，记录具体冲突，只暂停受影响的任务并请求裁定，其他任务继续。
