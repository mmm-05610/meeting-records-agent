# 第一版行为规格

来源：D0.1-r1 第 1–9、11 节。沿用 F01–F10 和原验收 T01–T18；本包开发任务使用 T001–T025，最终验收使用 A01–A24，三者不要混用。

## 用户场景

| 场景 | Given / When / Then | 对应需求 |
|---|---|---|
| US1 导入与归档 | 已登录本地账号并创建项目；导入 TXT/Markdown 并填写会议字段；只有入库、分块、归属核对完成才可查询 | F01、F02 |
| US2 查事实与分工 | 选定项目或会议；询问负责人、日期、讨论内容；答案来自当前范围，逐项有引用，未记载的内容不补写 | F02、F03、F06 |
| US3 查最新决定与变化 | 存在多场会议且上传顺序不同；询问最终决定或为何改变；按会议时间核对全部选定会议，区分提议、确认、变更与冲突 | F04、F05 |
| US4 追问与恢复 | 已完成一轮回答；追问、刷新或正常重启；理解必要指代并恢复当时范围、回答及稳定引用 | F06、F07、F08 |
| US5 移除错误记录 | 某会议已被引用；移除该记录再提问；新答案不再用它，旧答案保留但来源标为失效 | F09 |
| US6 检验可靠性 | 固定模拟题集与模型配置；运行评测及故障用例；输出逐项真实结果、失败样例、耗时和成本，不以替身结果代替产品成绩 | F10 |

## 不变约束

- **N01 复用边界**：沿用现有应用和组件；不得另建业务数据库、队列、工作流引擎或聊天框架。
- **N02 数据边界**：同一 PostgreSQL 实例中的 `agent_db` 与 `rag_db` 分开迁移和账号；一个文档只属于一个项目。
- **N03 证据边界**：范围与身份由服务器确认；模型输出和原文不能改变工具权限。历史聊天只用于指代，不能作为新的事实证据。
- **N04 完整性**：决定类问题须完成全部选定会议核对；预算不足或读取失败时明确中止该结论。
- **N05 本地运行**：Web 仅绑定 loopback，其他应用和数据库在内部网络；单账号登录，无产品注册入口。
- **N06 可复现**：锁定来源、依赖与实际模型配置，保留许可，发布安装方法和证据。
- **N07 恢复检查**：开发执行者第一步建立本次北京时间 01:30–09:30、每半小时一次的恢复检查，接续原任务，避免重入。它是开发执行保障，不是产品后台恢复能力。

## 完成条件

通过 [A01–A24](acceptance/checklist.md)，在全新安装环境完成“登录—建项目—导入—问答—引用—追加会议—重启恢复—移除”的演示。真实模型评测有原始结果和失败分析，契约/范围/来源的硬性用例逐项通过。

不预设未经批准的准确率或性能百分比。生成质量、token、成本和延迟按固定题集真实测量；将失败或缺凭据标为未通过/阻塞。能启动空页面、只有 mock 测试或仅有设计文档均不算第一版完成。

## 首版不包含

录音、语音转写、自动入会、外部同步、团队共享、任务派发、独立议题时间线、任意历史时点查询、产品后台任务队列及任意机器故障后的运行自动续做。仅承诺已完成会话的正常重启恢复。
